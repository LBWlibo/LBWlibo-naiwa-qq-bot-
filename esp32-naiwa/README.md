# 奶娃实体机 · 方案（ESP32-S3）

> 目标：一个摆在桌上的奶娃，按一下按钮说话，用**贝利亚声线**回你，高兴了甩一段奶蛙笑声。
> 不做 24 小时在线，用完就关——不依赖 QQ，不需要电脑常开（云后端另说）。

---

## 一、它能做什么

```
[按一下按钮]
   ↓
ESP32 录 3 秒（16kHz 单声道）
   ↓  WiFi POST 音频
后端：ASR 识别 → 人格（奶娃）→ LLM 回复 → TTS（贝利亚腔）
   ↓  返回 16kHz PCM 音频
ESP32 边收边播
```

延迟预估 **1.5–3 秒**（取决于后端在哪）。

## 三、接线

### INMP441（麦克风）

| 模块 | ESP32-S3 |
|---|---|
| VDD | 3V3 |
| GND | GND |
| L/R | GND（选左声道） |
| WS | GPIO 4 |
| SCK | GPIO 5 |
| SD | GPIO 6 |

### MAX98357A（功放）

| 模块 | ESP32-S3 |
|---|---|
| VIN | 5V（USB 供电脚） |
| GND | GND |
| LRC | GPIO 15 |
| BCLK | GPIO 16 |
| DIN | GPIO 17 |
| GAIN | 悬空（默认 9dB） |

喇叭接模块的 `+` / `-`。

### 按键

`GPIO 18` → 按键 → `GND`（内部上拉，按下为低）

> ⚠️ 麦克风和功放都用 I2S，但**必须用两组不同的 I2S 外设**（ESP32-S3 有 I2S0/I2S1），代码里分别 `I2S_NUM_0` 收、`I2S_NUM_1` 发。接同一组会互相打架。

## 四、后端三种选择

| 方案 | 需要什么 | 优点 | 缺点 |
|---|---|---|---|
| **A. 自己电脑当服务器**（推荐先做这个） | 电脑开着、同一 WiFi | 零成本，能用上本机已有的 ASR/TTS/人格 | 电脑关了就哑了 |
| **B. 云函数 / 小云主机** | 一台 1 核 1G 的 Linux（¥10/月） | 电脑关着也能用 | 要部署、要 API key |
| **C. 纯云 API（不自己写后端）** | 讯飞/阿里云的 ASR+TTS + DeepSeek API | 最省事 | 三份 key、按量计费 |

**建议：先 A 做通，再决定要不要搬 B。** 硬件调通比后端重要得多。

## 五、后端需要的组件（方案 A）

| 环节 | 用什么 | 现状 |
|---|---|---|
| ASR | **sherpa-onnx + SenseVoice**（本机已随 DSH 装好） | ✅ 已在 `~/.dsh/dsh-runtimes/.../node_modules/sherpa-onnx-win-x64` |
| 人格 | 直接复用现有的奶娃人格文本 | ✅ 在 `build-patch.py` 里 |
| LLM | **DeepSeek API key**（platform.deepseek.com，充 ¥10 够用很久） | ❌ 需要你去申请 |
| TTS | Edge 在线合成 + 降 4 半音滤镜（贝利亚腔） | ✅ 已实现于 `edge_tts.js` + `qq.py` |
| 笑声 | 奶蛙原声 `sounds\naiwa-laugh.mp3` | ✅ |

**唯一的缺口是 DeepSeek API key。** 没有它，后端只能回固定句子（可以先这样验证硬件链路）。

## 六、实施顺序（每步都可独立验证）

| 阶段 | 做什么 | 验收 |
|---|---|---|
| **1** | 接线 + 烧录「录音回声」固件：录 3 秒，存 PSRAM，再播出来 | 对着麦克风说话，喇叭里听到自己的声音（有延迟正常） |
| **2** | 接 WiFi，把录音 POST 到电脑上的测试服务器，服务器原样回传 | 说话 → 电脑收到 wav 文件 → 喇叭播放 |
| **3** | 后端接 ASR，把识别文字显示在串口 | 串口打印出你说的话 |
| **4** | 后端接 LLM + TTS，返回贝利亚腔语音 | 按按钮说话，听到它用贝利亚腔回你 |
| **5** | 加圆屏显示奶蛙表情 / 加第二颗按键触发笑声 | 完整玩具 |

**不要跳步。** 音频链路是最容易出问题的地方（I2S 时钟、采样率、回声自激），
一步一验，出问题能立刻定位。

## 七、已知难点（提前说）

1. **回声自激**：喇叭外放时麦克风会听到，形成啸叫。对策：录放不要同时；播放时把麦克风静音。
2. **PSRAM 内存**：16kHz×2 字节×3 秒 = 96KB，8MB PSRAM 绰绰有余，但要用 `heap_caps_malloc(..., MALLOC_CAP_SPIRAM)`。
3. **HTTPS 握手吃内存**：ESP32 的 mbedTLS 握手峰值约 40–50KB，走 HTTPS 要留足栈，必要时用 HTTP（局域网内）。
4. **供电**：功放开 3W 时有电流冲击，USB 口供电不足会导致复位。用质量好的线，或功放单独供电（共地）。
